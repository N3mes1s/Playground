# LLM-as-Computer: Complete Architecture

Following [Percepta's "Can LLMs Be Computers?"](https://percepta.ai/blog/can-llms-be-computers)

## What We Built

A WebAssembly interpreter that runs entirely inside a vanilla transformer's forward pass. Programs are encoded as tokens, and the model generates execution traces step by step — no external tools, no VM at inference time.

## Two Approaches

### 1. Hand-Crafted Weights (Compiled Interpreter)
We manually set transformer weights to implement WASM operations as circuits:
- **ADD/SUB**: 32-bit with carry/borrow chains across 4 bytes
- **MUL**: 32-bit via bilinear gates + two-stage modular reduction + carry via dim 0 trick
- **Comparisons/EQZ**: 24-bit using 256x byte-1 and 65536x byte-2 weights
- **CONST**: 32-bit via 4-byte immediate packing
- **Locals**: copy via explicit-address attention
- **Control flow**: hybrid encoder (VM for IP sequence, model for values)

**Limitations**: DIV, REM, AND, OR, XOR, SHL, SHR cannot be hand-crafted because step-function thresholds depend on variable operands.

### 2. Trained Weights (Learning from Execution Traces)
We train the transformer on execution traces generated by a reference VM:
- Model learns ALL WASM operations including the "impossible" ones
- Compiled weights as initialization (or random init)
- Teacher forcing with cross-entropy loss on trace tokens
- Structurally diverse training data prevents positional shortcuts

**Current best**: 98.5% token accuracy, 9-10/11 operations pass autoregressive test.

## Trace Format
Each execution step = 5 tokens: `[byte0, byte1, byte2, byte3, commit]`
- Bytes: little-endian i32 value
- Commit: stack_size (0-253), 254 = OUTPUT, 255 = HALT

## Program Encoding
Each instruction = 6 tokens: `[opcode, imm_b0, imm_b1, imm_b2, imm_b3, delta+1]`
- Padded to MAX_INST instructions + 1 SEP token

## Training Pipeline

### Data Sources
1. **Random program generator**: arithmetic, chains, locals, loops, conditionals
2. **WASM spec test suite**: 323 test vectors from WebAssembly/spec (i32.wast)
3. **Rust fast VM**: 1.2M traces/sec for massive data throughput

### Training Process
1. Generate program → encode as tokens
2. Run VM to get ground truth trace
3. Teacher forcing: input = program + trace[:-1], target = trace (shifted by 1)
4. Cross-entropy loss on trace positions only (program positions masked)
5. AdamW optimizer, cosine LR schedule

### Key Insight: Diverse Training Data
Simple `CONST, CONST, OP` programs cause positional shortcuts. The model learns "byte 10 = f(byte 0, byte 5)" instead of understanding operations. Fix: structurally diverse programs (chains, locals, loops) force the model to learn operation SEMANTICS.

## Hand-Crafted Weight Architecture (d_model=40)

### Dimension Allocation
| Dim | Name | Source |
|-----|------|--------|
| 0 | byte_value | Token embedding (NEVER modified — the carry trick) |
| 1 | stack_key / prevB | L0 FFN / L3 attention |
| 2 | opA_byte1 | L2 attention head 2 |
| 5-6 | position / -S*pos² | PE (quadratic addressing) |
| 7 | step_number / IP | PE |
| 8 | slot (0-4) | PE |
| 9 | is_commit_slot | PE |
| 10-15 | opcode flags | Token embedding |
| 17 | prev_ss + delta+1 | L0 heads 10+11 |
| 19 | prevA / commit_key_quad | L3 head 0 / L0 FFN |
| 23-24 | opA_byte / opB_byte | L2 heads 0-1 |
| 25 | ALU result accumulator | L2+ FFN (output head reads this) |
| 26-27 | opB_byte1, cleared / bias | L2 head 3 / PE |
| 28 | is_commit_input | PE (slot 0 indicator) |
| 29 | MUL scratch (a[k-1]*b[k-1]) | L3 FFN |
| 30-31 | cmp flags / k-2 fetch | Token embed / L3 attention |
| 36-37 | is_slot_2 / is_slot_3 | PE (exact slot gating) |
| 38-39 | opA_byte2 / opB_byte2 | L2 heads 4-5 |

### Layer Architecture (10 layers)
- **L0**: Instruction fetch (12 heads) + previous commit reader
- **L1**: Stack-based operand resolution (content-matching attention)
- **L2**: Byte fetch (6 heads) + ALU (ADD/SUB/MUL/CONST/COPY/comparisons/EQZ/commit)
- **L3**: Carry detection + k-1/k-2 fetch + MUL cross terms + SUB borrow + dim clearing
- **L4**: Byte-2/3 cross terms + carry recomputation with exact slot gating
- **L5**: carry_0 propagation
- **L6**: carry_1 propagation + ADD mod 256
- **L7**: MUL mod 4096 (slot 0) + MUL carry byte0→1 + carry_2 + SUB mod
- **L8**: MUL mod 4096 (all slots)
- **L9**: MUL mod 256 (all slots)

### Key Innovations
1. **dim 0 carry trick**: Input token byte_value is NEVER modified by any layer. At slot k, dim 0 = byte_{k-1} result. Carry = (raw_total - dim0) / 256.
2. **Two-stage modular reduction**: mod 4096 (16 step pairs) → mod 256 (15 step pairs) handles products up to 65536.
3. **Exact slot gating**: PE dims 36-37 mark slot 2/3 for byte-specific operations.
4. **Structural pop correction**: br_if/if pops tracked via PE dim 17 correction.

## Rust Engine
- `generate_trace_multilayer()`: multi-layer inference with 2D convex hull attention
- `fast_vm_trace()`: 1.2M traces/sec WASM VM for training data generation
- Hull2D: O(log n) max-dot-product queries on convex hull boundary
