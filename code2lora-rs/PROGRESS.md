# Code2LoRA-rs — project log & findings

A running record of what was built, what we measured, the honest gaps, and the
decisions made — so none of it is lost. Detailed tables live in `README.md`,
`SECURITY.md`, `tinker/RESULTS.md`, and `tinker/RESULTS_multilang.md`; this file
is the index + the things not captured elsewhere.

Paper: **Code2LoRA** — *Hypernetwork-Generated Adapters for Code LMs under
Software Evolution* (arXiv:2606.06492). Core claim: inject repository knowledge as
LoRA **parameters** (generated by a hypernetwork in one forward pass) instead of
**retrieved context**, with zero inference-time token overhead.

## Headline results (all live on real models)

- **Generated adapter runs on the real model.** Rust-generated PEFT adapter loads
  onto **Qwen2.5-Coder-1.5B** via PEFT and generates (`peft_local.py`). (Hypernet
  untrained ⇒ ≈parity; the deliverable is real-model attachment/execution.)
- **Parametric beats RAG.** Python 3-repo: repo-LoRA **62.5%** vs RAG ~38% vs base
  41.7%. Cross-language 9 repos (JS/Rust/Go): repo-LoRA **55.6%** mean, wins **8/9**;
  RAG = base (27.8%) at ~4× tokens. (`tinker/RESULTS*.md`)
- **Scaling raises the ceiling, every language.** cachetools (Py) 60→**92%**;
  lodash (JS) 50→75%; serde-json (Rust) 43.8→71.9% (flips RAG); gin (Go) 12.5→71.9%.
- **Hypernetwork learns + generalizes.** Pure-Rust autograd: held-out adaptation
  error **260 → 2.2 (−99.2%)** on unseen repos.
- **Semantic conditioning.** Neural embedder: two differently-worded HTTP repos →
  adapter cosine **0.74** vs **0.39** to a math repo (hash: 0.51 vs 0.11).
- **Evo trajectory.** Per-commit adapter evolution, order-sensitive, deterministic.

## Security tangent — findings (kept here so they're not lost)

Goal: use Evo to flag malicious commits. Tested on a synthetic injection and the
two REAL supply-chain attacks whose commits survive in public history.

`commit_anomaly.py` (bge-large embeddings, multiple scorers), rank of the malicious commit:

| repo / attack | state-jump | centroid | **kNN (k=3)** | trained predictor |
|---|---|---|---|---|
| `Marak/colors.js` `074a0f8` (real Jan-2022 DoS) | #18/40 | #13/40 | **#1/40 ✅** | #40/40 |
| `tukaani-project/xz` `cf44e4b7` (real CVE-2024-3094) | #14/40 | #5/40 | #6/40 | #36/40 |
| `facebook/react` + planted overt exfil (synthetic) | #24 (hash) / #3 (neural) | — | — | — |

Conclusions (honest):
- **kNN local-outlier on semantic embeddings catches the real colors.js DoS at #1** —
  the payload fools the global mean (camouflaged as idiomatic colors string-styling)
  but has no close neighbours. `evo-scan --method knn` (now default) ports this; the
  Rust mean+max embedding is weaker than pure mean-pool, and empty/merge commits must
  be filtered (zero-norm diffs otherwise score 1.0).
- **xz still evades text-based detection** (best #5–6, top 15%) because the payload is
  in **binary** test files — exactly why it evaded human review. Needs binary/entropy
  features.
- Untrained novelty catches blatant foreign code, not real camouflage. It's a triage
  *prior*, not a detector. Full writeup: `SECURITY.md`.

## The one real gap in the core claim

The *measured* repo-adaptation gains come from the **per-repo LoRA training loop**
(the paper's upper-bound baseline), not yet from the hypernetwork's **one-pass
generation** (which is at initialization ⇒ near-identity). Closing this = training
the hypernetwork **through a real base model**, which is GPU-bound:
- this container is **CPU-only**;
- **Tinker** trains only its own LoRA — it cannot backprop into a custom hypernetwork.

So one-pass generation producing real gains is the open end-to-end step. Halves of
it are each proven: the hypernetwork *learns/generalizes* (`train-demo`, small scale)
and a *trained* adapter on the real model *beats RAG* (per-repo LoRA).

## Decisions / environment notes

- Live model is **Qwen/Qwen3.5-4B** (Tinker's catalog lacks Qwen2.5-Coder-1.5B);
  the Rust crate keeps Qwen2.5-Coder-1.5B as the offline structural target.
- Default embedder is feature-hashing (offline, no deps); `--features neural` adds
  candle + bge-large.
- TLS-intercepting proxy: `hf-hub`'s bundled roots reject the proxy CA → download
  models with a system-trusted tool and pass the local dir to `--embed-model`.
- Tinker API key is provided via `TINKER_API_KEY` (never committed).
